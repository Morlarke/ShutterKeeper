# 快门闪选（ShutterKeeper）

macOS 原生摄影工作流工具，用来替代 Adobe Bridge 的 **导入 / 批量改名 / 审阅打分** 三个环节，
并为 Lightroom Classic 准备好星级元数据。

Swift + SwiftUI 编写，**零第三方依赖**（只用系统框架与系统自带 SQLite）。

* 版本：**beta0.1**
* 作者：快门镖局-陈师 · [thechengsir@foxmail.com](mailto:thechengsir@foxmail.com)
* 许可证：**MIT**（见 [LICENSE](LICENSE)）

## 构建与运行

环境要求：macOS 14 或更高；Xcode 或匹配系统的 Command Line Tools。

```bash
# 1. 构建并打包成 .app
Scripts/build-app.sh            # 默认 release

# 2. 运行
open "build/快门闪选.app"
```

也可以直接跑命令行部分：

```bash
swift build
swift run skctl selftest        # 完整自检，51 项检查
```

> 首次运行需要在「系统设置 → 隐私与安全性」里允许它访问照片所在目录。
> 应用**未启用 App Sandbox**（和 Bridge 一样），这样才能自由读写 SD 卡、任意文件夹和废纸篓。

想把它发布到 GitHub，见 [PUBLISH.md](PUBLISH.md)（含一键脚本与协议选择）。

## 命令行工具 `skctl`

界面还在施工期间，元数据相关的一切都可以先用它验证：

```
skctl paths                     显示数据库与缓存目录
skctl scan <文件夹>              扫描文件夹，列出「一张片子」分组
skctl info <文件>...             显示相机、镜头、拍摄时间、曝光、尺寸
skctl get <文件>...              从文件里读取星级（含 ImageIO 交叉验证）
skctl rate <0-5> <文件>...       写入星级（RAW 写 .xmp，JPG 写内部元数据）
skctl check <jpg文件>...         查看 JPEG 段布局与像素数据位置
skctl preview <文件> [最大边长]   验证大图加载耗时（默认 3000）
skctl review <文件夹>            用真实文件夹跑一遍审阅流程（只读，不写盘）
skctl lr <文件夹> [--apply]      读取 Lightroom 目录里的星级（--apply 才写盘）
skctl selftest                  完整自检
```

### 用 Lightroom Classic 验证星级（推荐做一次）

```bash
# 拿一份副本测试，不要直接动原片
cp -R ~/Pictures/某文件夹 /tmp/sk-lr-test
skctl rate 4 /tmp/sk-lr-test/IMG_0001.NEF
```

然后打开 Lightroom Classic，导入 `/tmp/sk-lr-test`，看这张 RAW 是不是 4 星。
在 LR 里打开「目录设置 → 元数据 → 自动将更改写入 XMP」，再改一次星级，
就能验证双向同步（LR 写回侧车文件，快门闪选读得到）。

### 为什么「我在 LR 里打过分，软件却读不到」

Lightroom Classic **默认不会**把星级写进文件。「自动将更改写入 XMP」是关闭的，
这时星级只存在目录数据库（`.lrcat`）里，任何第三方软件都看不到 —— 这不是读取失败。

快门闪选默认会**直接读 Lightroom 目录**（只读），所以这种情况下你也能在审阅界面看到星级，
顶栏会提示「N 张的星级来自 Lightroom 目录」。如果你希望星级也写进文件本身，有两条路：

1. **让 LR 写文件**（推荐）：目录设置 → 元数据 → 勾选「自动将更改写入 XMP」，
   然后全选照片按 ⌘S 执行「将元数据保存到文件」。NEF 会生成 `.xmp` 侧车，
   JPG 会写进文件内部 XMP。之后快门闪选正常读取。
2. **让快门闪选帮你写**：审阅菜单 →「从 Lightroom 目录导入星级…」（或顶栏的「写入文件」按钮），
   命令行则是 `skctl lr <文件夹> --apply`。软件只读 `.lrcat`，把目录里的星级写进文件，
   正好也是 LR 的 ⌘S 会做的事。

注意第 2 条只同步**目录里已评分**的照片；目录里没打分的不会被清零。

## 关键设计决策

### 1. 支持的格式与星级写到哪里

| 文件类型 | 显示 / 配对 / 改名 | 星级写入位置 | Lightroom 能读到吗 |
|---|---|---|---|
| 专有 RAW（NEF / NRW / CR2 / CR3 / ARW / RAF / RW2 / ORF / PEF / SRW / RWL / GPR / INSP …） | ✅ | 同名 `.xmp` 附属文件 | 能，和 Bridge 一致 |
| JPEG（jpg / jpeg / jpe / jfif） | ✅ | 文件内部 XMP（APP1 段，原地） | 能 |
| **TIFF / TIF** | ✅ | 文件内部 XMP（tag 700，原地） | 能 |
| **PNG** | ✅ | 文件内部 XMP（iTXt 块，原地） | 能 |
| DNG | ✅ | 文件内部 XMP（tag 700，原地） | 能（相机直出、内部没有 XMP 段的 DNG 只能记在软件内，会明确提示） |
| HEIC / HEIF | ✅ | 只记在软件内 | 暂不能 |
| PSD / PSB | ✅ | 只记在软件内 | 暂不能 |
| BMP / GIF / WebP / AVIF / JP2 / EXR / TGA / PCX / ICO | ✅ | 只记在软件内 | Lightroom 也不读这些格式的星级 |
| 视频（MOV / MP4 / M4V / AVI / MTS / MXF / MKV / R3D / BRAW …） | ✅ | 不打分 | — |
| `.xmp` / `.aae` / `.thm` / `.lrv` / `.dop` / `.pp3` 附属文件 | 不单独显示 | 跟着主文件一起改名 | — |

**原地写入**：TIFF 与 PNG 只改写文件内部 XMP 那一段字节（必要时吃掉 XMP 自带的空格 padding
来腾出空间），文件长度不变、图像数据一个字节都不动。已用真实文件验证：
182 MB 的扫描 TIFF 写入后除 XMP 段外逐字节一致；PNG 只变了 1 个星级数字 + 4 字节 CRC。

JPG 写入采用**原地替换 XMP 数据段**的做法：像素数据、原始 EXIF、文件大小都不变，
只有 XMP 段和文件修改时间变化。这条路径已用真实的 13 MB 相机 JPG 验证过，写入前后
从 SOS 标记到文件末尾的压缩像素数据 md5 完全一致。

已有 `.xmp` 文件（例如 Lightroom 写过修图设置）时**只更新星级字段**，
其余内容逐字节保留。已用一份真实 LR 侧车文件验证：13188 字节进、13188 字节出，
120 个 `crs:` 修图字段一个不少。

### 2. 哪些格式暂时只记在软件内

* **HEIC / HEIF**：ISO BMFF 封装，写入内部 XMP 需要重排 box，复杂度高，先只记软件内。
* **PSD / PSB**：要改 Photoshop 图像资源块（8BIM 0x0424）并重排后续数据，风险大，先只记软件内。
* **BMP / GIF / WebP / AVIF / JP2 等**：Lightroom 本身也不读这些格式的星级，只记软件内。
* **没有 XMP 段的 DNG**（相机直出）：没有安全的位置可写，只记软件内，打分后会明确提示。

这些情况的星级仍然可用于筛选、排序和批量改名，只是不会出现在文件里。

### 3. 「一张片子」模型

软件内部以 `AssetGroup`（配对组）为最小单位，而不是以文件为单位。
RAW + JPG 配对后，胶片条只出现一项、打分联动、删除整对处理、筛选也按张算。
配对依据是同一文件夹内主文件名相同（忽略大小写）；视频不与同名照片合并。

### 4. 数据存储

```
~/Library/Application Support/ShutterKeeper/
├── db/ratings.sqlite      ← 评分数据库、最近项目、导入/改名历史
└── cache/thumbs/          ← 缩略图缓存
```

两者互相独立，可以分别删除：

* 删缓存：下次重新生成，不损失数据
* 删数据库：软件自己的记录没了，但文件里的星级仍在；重新打开文件夹时会从
  `.xmp` 与 JPG 内部元数据恢复（`skctl selftest` 里覆盖了这条恢复路径）

目录名用 ASCII（`ShutterKeeper`），界面显示中文名，避免第三方工具处理中文路径出问题。

### 5. 界面与交互

* 三个模块用顶部标签页切换，彼此独立，想用哪个点哪个
* 启动显示最近打开的文件夹，点击直接进入
* 默认深色（中性灰），可在白 / 浅灰 / 中性灰 / 黑之间切换，控件明暗跟着背景亮度走
* 视频用内嵌 AVKit 播放，不调外部 Preview

### 6. 审阅模块的操作方式

界面是「顶部信息条 + 中央大图 + 右侧 EXIF 面板 + 底部胶片条」。胶片条里配对组只出现一项，
大图优先显示 JPG（RAW 单张则显示 RAW）。

| 操作 | 按键 |
|---|---|
| 打分 0–5 星 | 数字键 0–5（视频不打分） |
| 上一张 / 下一张 | ← / → |
| 按日期跳组 | ↑ / ↓（照片） |
| 打开上一级文件夹 | ⌘⌥↑ |
| 显示 / 隐藏文件夹面板 | ⌘⌥B |
| 视频音量 | ↑ / ↓（视频播放时） |
| 视频播放 / 暂停 | 空格（视频） |
| 照片全屏 | 空格；Esc 退出 |
| 视频全屏 | 双击画面 |
| 显示 / 隐藏 EXIF 面板 | P |
| 显示 / 隐藏胶片条 | Tab |
| 筛选星级 | ⌘⌥0 清除，⌘⌥1–5 显示 ≥N 星 |
| 缩略图大小 | ⌘+ / ⌘- |
| 适应窗口 | ⌘0（与 Bridge 一致） |
| 1:1 像素 | ⌘⇧0 |
| 画面放大 / 缩小 | ⌘⇧+ / ⌘⇧-（或滚轮） |
| 删除（进废纸篓） | ⌫ / ⌦ |
| 切换模块 | ⌘\\ / ⌘⇧\\ |

* 滚轮缩放、拖拽平移，最大放大到 1:1 设备像素；放大接近 1:1 时自动换成原始分辨率。
* 预览区右上角一直显示当前缩放比例，到达像素级时显示「1:1 像素」。
* **在大图区域右键**可以直接切换背景色（白 / 浅灰 / 中性灰 / 黑），和偏好设置里是同一项；
  浅色背景下图片会有一圈细描边，避免白色照片和背景糊在一起。
* 大图与相邻的 ±2 张会预加载，切换几乎无延迟（实测 45 MP RAW 首次 148 ms、缓存命中 0.1 ms）。
* 空格与上下方向键的含义按场景区分：照片是全屏/跳组，视频是播放/音量。
* 打分是联动的：RAW + JPG 两种格式写入同样星级。
* 筛选实时生效；当前这张被筛掉时自动跳到下一张符合条件的。
* 正在输入文字时，单键快捷键自动让行。
* 快捷键可在偏好设置里逐项更改，冲突时会问「覆盖 / 取消」。

### 7. 文件夹导航（访达分栏视图）

### 模块之间的默认文件夹

* **改名模块**默认进入「最近导入的文件夹」（还没有导入过就退回到最近打开/用过的文件夹）
* **导入模块**的来源默认选**插着的外接设备**（优先有 DCIM 的 SD 卡/读卡器，其次其它可推出外接盘）；
  系统盘那个 `Macintosh HD → /` 的符号链接会被跳过
* **审阅模块**默认进入改名模块正在处理的那个文件夹：改名完成后会自动切过去，
  之后每次切到审阅标签、只要两边文件夹不一致也会同步过来（一致就不重复扫描）

导入模块（M4）完工后会调用 `AppState.noteImportedFolder(_:)` 把目标文件夹记下来。

审阅界面左侧是文件夹面板，操作方式跟着访达的分栏视图走（⌘⌥B 或顶栏按钮开关，分隔条可以拖动调宽）：

* 每一列列出「上一列选中文件夹」里的子文件夹，点中就在右边展开它的内容，同时把该文件夹打开到审阅区
* 最左一列是当前文件夹往上第 3 级的父目录，所以左右翻兄弟文件夹也很方便
* 点过的层级会在当前路径里保留；用「上一级」按钮（⌘⌥↑）或打开其它文件夹时会重建路径
* 打开一个只有子文件夹、自己没有照片的目录时，预览区会直接列出子文件夹让你点进去

### 8. 星级从哪来

审阅界面显示的星级按下面的顺序取值：

1. **文件本身**：RAW 的同名 `.xmp`、JPG 的内部 XMP（这也是写给 Lightroom 的那份）
2. **Lightroom 目录**：文件里没有、但 LR 目录里有分时，会补上并显示，同时顶栏出现橙色提示「N 张的星级来自 Lightroom 目录」和「写入文件」按钮

第 2 条默认开启，可以在偏好设置里关掉。它只读 Lightroom 的 `.lrcat`，不会修改 LR 的任何文件；
点「写入文件」才会真正把星级写进照片（和在 LR 里按 ⌘S 的效果一样）。
目录里的「未评分」不会把文件里的星级清零。

### 9. 批量改名（M3）

模板是 `日期_自定义文本_序列号`，例如 `20260927_婚礼_001.CR3`。

界面从上到下三层：**功能条 → 改名控制区 → 素材浏览区**。改名控制区固定在浏览区上方，
所以切换视图也不会看不到改名设置。浏览区直接采用访达的视图模式（默认进入最近用过的文件夹）：

* **⌘2 分栏视图（默认）**：逐级往下的列视图，最后一列列出当前文件夹里的素材，
  每个文件下面直接显示改名后的名字
* **⌘1 图标视图**：文件夹 + **全部素材文件**（RAW、JPG、HEIC、视频、以及 `.xmp` 侧车）
  的缩略图网格，每个文件下面显示改名结果

分栏视图支持键盘操作（跟访达一致）：**↑↓** 在当前列移动、**→** 进入选中的文件夹、
**←** 回到上一级并把高亮落在刚离开的那个文件夹上。在输入框里打字时，单键留给输入框，
但 ⌘1／⌘2 这类组合键依然有效；点一下素材区就会结束输入，方向键随即回到文件夹导航。

* 按 **拍摄日期** 分组（照片取 EXIF，视频取文件创建日期）；同一天的照片共用一个自定义文本
* 序列号每组从 1 开始，位数可选（默认 3 位）；**视频单独一套序列号**，不与照片混编
* RAW + JPG 配对后共用同一个主文件名，只保留各自扩展名
* 同名附属文件跟着一起改：`.xmp`（Lightroom 侧车）、`.aae`、`.thm`、`.lrv`、`.dop`、`.pp3`，
  同时兼容 `IMG_1234.xmp` 与 `IMG_1234.NEF.xmp` 两种写法
* 界面只显示一个模板示例；每组一行填自定义文本，也可以用「统一填写」一次性套用到所有组
* **自定义文本可以加段**：点 + 最多加到 4 段，模板变成 `日期_文本1_文本2_文本3_序列号`，
  例如 `20260927_婚礼_新娘_精修_001.CR3`；留空的段会自动跳过，不会出现连续下划线
* 控制区高度跟着分组数量走（最多约两行半），剩下的空间全留给素材区
* 目标文件名已存在时停下来询问：跳过冲突项 / 覆盖（旧文件进废纸篓）/ 取消
* **⌘Z 撤销**上一次改名（编辑菜单里也有同样的菜单项），仅在本次运行期间有效

改名采用「两段式」搬运（先全部改成临时名，再改成最终名），所以 A→B、B→C 这类链式改名、
甚至两个文件互换名字都不会互相覆盖。

命令行同样可用（默认只预览，加 `--apply` 才真的改；命令行执行完会自动撤销回去，
所以它适合拿来做验证）：

```bash
swift run skctl rename "/路径/文件夹" --text 婚礼 --digits 3          # 预览
swift run skctl rename "/路径/文件夹" --text 婚礼 --apply             # 执行（会自动撤销回来）
```

模块切换快捷键改成了 **⌘⌥1 / ⌘⌥2 / ⌘⌥3**（⌘1、⌘2 让给改名模块的视图切换），
⌘\\ / ⌘⇧\\ 依然可以在三个模块之间循环。

### 10. 导入（M4）

界面从上到下四层：**来源 → 项目设置 → 源文件按拍摄日期分组预览 → 进度与执行**。

* **来源**：自动列出 `/Volumes` 下挂载的卷并标注哪个有 DCIM 目录；也可以直接选任意文件夹
* **项目文件夹**：`<目标位置>/<日期_项目名>/`，日期默认取源文件里最早的 EXIF 拍摄日期
  （可以手填覆盖），两段都可以留空。里面固定分 `Photos/` 与 `Videos/`
* **配对**：同主文件名的 RAW+JPG 视为一张，`Photos/` 里两个文件都在；`.xmp` 等附属文件跟着走
* **预览**：按拍摄日期分组显示缩略图，配对组只出现一格并标注 RAW+JPG
* **冲突**（需求文档 5.5）：
  * 目标项目文件夹已存在 → 问你「合并进已有文件夹 / 新建带后缀的文件夹（`婚礼-2`）/ 取消」
  * 卡里这个文件之前导入过（同名同大小，查导入历史）或目标已有同名文件 → 问你「跳过 / 覆盖（旧文件进废纸篓）/ 取消」
* **进度与取消**：进度条 + 当前文件名 + 剩余时间，随时可以取消；取消后目标里不会留下半个文件
  （拷贝先写临时文件，校验大小之后再改名就位）
* **备份**：勾选后把同样的结构复制到备份位置，路径记住上次选择；备份失败会明确报出来
* **收尾**：全部导入完成后统一弹窗询问是否把**已确认导入**的卡内原文件移入废纸篓（不会动没导入成功的）

命令行同样可用（默认只预览）：

```bash
swift run skctl import "/Volumes/NIKON Z5" --dest ~/Pictures --name 婚礼           # 预览
swift run skctl import "/Volumes/NIKON Z5" --dest ~/Pictures --name 婚礼 --apply   # 真导入
# 可选：--backup <目录> --merge --overwrite --delete-source --db <历史库路径>
```

## 已按需求确认的取舍

* **视频方向键**：播放时上下键调音量（↑↓ 按日期跳组改由其他修饰键承担，M2 里落实）
* **DNG / HEIC**：首版只存软件内评分（理由见上）
* **审阅视图**：只做大图 + 底部胶片条一种，不做网格视图
* **界面语言**：简体中文单语，结构上预留本地化
* **数据库恢复询问时机**：仅当数据库里没有该文件夹的记录时才询问
* **删除**：整对删除（RAW + JPG + 对应 `.xmp`），进废纸篓，删除前确认

## 已知限制

* **界面部分没有做真机启动验证**：开发环境的沙盒进程连不上 WindowServer，
  GUI 无法由我这边启动（命令行部分已用真实文件充分验证）。审阅模块的实际观感与交互
  需要你在本机打开后确认。
* **`swift test` 在只有 Command Line Tools 的环境里会卡住**：swift-testing 的测试运行器
  在这种环境下启动异常。请用 `skctl selftest` 作为验证路径；装好 Xcode 之后可以再跑
  `swift test`（测试代码本身是完整的）。测试覆盖的内容与 `skctl selftest` 一致。
* **没有扩展 XMP（Extended XMP）支持**：超过 64 KB 的 XMP 数据包无法写进单个 JPEG 段。
  正常拍摄的照片不会触发；除非外部软件塞了超大 XMP。
* **RAW 文件里的内嵌 XMP 不动**：星级只写侧车文件（与 Bridge 行为一致）。
  个别相机在 RAW 里自带评分，Lightroom 的判断以侧车为准。
* **TIFF / DNG 的 XMP 只认 IFD0 里的 tag 700**：这是 Adobe 系软件的标准位置；
  极少数工具把 XMP 放在别处时会读不到（写入时会明确报「没有 XMP 段」）。
